Journey Session Sign Up

A proposal for a new Rock workflow to support picking Session 1, 2 and 3 separately on the website.

What's changing

On the new Journey event page, people choose a date and campus for each of the three sessions. Each session can be a different group, and at a different campus. One submission can include one, two or all three sessions.

The current workflows (1833 English, 1835 Spanish) take a single Group, so they can't handle this.

Proposal

  • Create one new workflow, "Journey Session Sign Up", for both English and Spanish. The split existed for the Rock forms, which this flow doesn't use.
  • Leave 1833 and 1835 untouched. The existing Journey Finder modal still uses them.
  • For each session sent, add the person to that group and set the group member attribute SessionN = True. This flag is how the group knows which session they're attending, and the website uses it to count capacity.
  • Match or create the person once, and send one combined confirmation email listing every session they picked.
  • The email's campus, sender and language come from the most-selected campus. When there's a tie, we use the campus of the earliest session. The website works this out and sends that group as Group, so the existing contact, Spanish and online Lava can keep working.

What the website will send

Attribute key Value
FirstName, LastName, PrimaryPhoneNumber, EmailAddress Same as today
AtCF, Reason, hopetoget Same as today (hopetoget is optional)
LaunchSource app
Group The group used for the email (most-selected campus)
Session1Group – Session3Group Group GUID for each selected session

Sessions the person didn't pick are left out entirely, and the workflow should skip them. The session number comes from the key, so Session2Group means "set Session2 = True on that membership". Session times come from the group's ClassOne, ClassTwo and ClassThree attributes, so the website doesn't send them.

Questions for you

  1. Childcare. The website doesn't ask childcare questions today, and the Rock childcare form can't show in an API launch. Should we drop childcare from this workflow, or add the questions to the website and send them once per submission?
  2. Adding sessions later. After signing up, people can come back and add the sessions they skipped. That launches the workflow again with only the new sessions. We plan for that email to list only the new sessions. Does that work?
  3. Combining English and Spanish. Are there any Spanish-only steps in 1835 besides the email that we'd lose by combining?
  4. Ownership. We'd like to build a first version ourselves so we can test end to end. Are you OK reviewing it and taking it over, or would you rather build it?
